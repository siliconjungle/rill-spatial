# Pending adapter capability audit

Read-only audit, 2026-10-20. Inventory pins below are authoritative; no source edits, builds, dependency installation or retained source copies were made. `research/coverage.json` is absent. `tools/coverage.py` currently derives coverage by mapping adapter names and rewrites inventory; it was inspected, not executed. An empty adapter list means unimplemented, not proven incompatible. The npm tarball was inspected in memory and its SHA-512 matched inventory.

**Conclusion:** none of these 12 is established to be an unrelated/non-spatial package. Native f64 candidates, all-population kNN adaptations and conservative broad-phase adaptations remain to implement. Several cannot natively implement the full arbitrary finite f64 contract; that is a capability limitation, not a reason to erase them from coverage. Native precision, candidate completeness, adapter fallback and actual build success must be recorded independently.

## Rules common to the adapters

Preserve arbitrary stable u64 IDs and coincident points with different IDs. Keep current f64 coordinates in authoritative adapter storage. Query a conservative candidate superset, then charge the existing ordered squared/scaled-hypot predicate and materialization to timing. In particular, f32 conversion or final filtering alone cannot repair candidates omitted by source pruning. Compute outward-rounded query boxes with an arithmetic guard appropriate to the contract, including radius-zero and rounded squared-distance boundaries; detect overflow. Handle unsupported/extreme inputs with an explicitly recorded, timed exact fallback. A fallback preserves adapter API semantics but does not demonstrate native indexing capability for that domain.

For all-population kNN, request the entire indexed population, not an estimated K; keep allocations/ranking/remapping/filtering in the timed operation. Rebuild static structures after updates and charge it to update/prepare. Do not leak borrowed input storage across iterations. Fail/report correctness losses rather than truncating or silently changing semantics.

## Native f64 or f64 all-population paths

**1. collision 0.20.1 — feasible, unimplemented.** Primary: [pinned crate](https://crates.io/api/v1/crates/collision/0.20.1/download), [source project](https://github.com/rustgd/collision-rs). `src/volume/aabb/aabb3.rs` defines generic `Aabb3<S>`; `src/dbvt/mod.rs` exposes `TreeValue`, `Visitor`, insertion, update/refit and query. Use `Aabb3<f64>` point leaves carrying IDs, a custom visitor with **closed** conservative overlap, and exact final filtering. The built-in `Discrete<Aabb3<S>>::intersects` uses strict inequalities at lines 234–239: zero-volume point boxes/boundary contacts can be lost, so `DiscreteVisitor` is unsuitable without padded boxes. Call `update()`/required `do_refit()` before queries; source warns internal bounds can be stale after mutation. No static precision blocker; historical cgmath/rand dependencies remain unbuilt in this audit. Do not mistake the f32 rotation-quality constant for f32 point storage.

**2. kdtree-plusplus, commit ab5118c86342d6bb195b4187f61f05911ebc0587 — feasible, unimplemented.** Primary: [pinned query implementation](https://github.com/nvmd/libkdtree/blob/ab5118c86342d6bb195b4187f61f05911ebc0587/kdtree%2B%2B/kdtree.hpp), [pinned region predicates](https://github.com/nvmd/libkdtree/blob/ab5118c86342d6bb195b4187f61f05911ebc0587/kdtree%2B%2B/region.hpp). Store a record with double coordinate accessor and u64 ID in `KDTree<3, Record>`. `find_within_range`/`visit_within_range` select an axis-aligned box: comments call this Manhattan distance, but implementation is coordinate-wise box/Chebyshev selection, not L1 or Euclidean. `_Region::encloses` and overlap are closed under the default strict comparator. Use an outward box, exact Euclidean final filtering, and source `optimise` where appropriate with its cost charged. Coincident records are not a reason to drop IDs; verify insertion/removal by full record. Header-only adapter needs no autotools installation. Build compatibility still untested. Inventory's `NOASSERTION` is incomplete metadata: retained COPYING and source headers identify Artistic License 2.0; do not use the missing metadata as a capability exclusion.

**3. bosque 0.2.0 — feasible all-N kNN adaptation, build-script caveat.** Primary: [pinned crate](https://crates.io/api/v1/crates/bosque/0.2.0/download). `src/float.rs` implements `TreeFloat for f64`; `src/tree.rs` has `build_tree_with_indices`, `nearest_k`, and `nearest_k_sep`. Build f64 XYZ data plus its parallel u32 permutation; map returned in-tree positions through that permutation to external u64 IDs. Request `k=population`, then exact-filter authoritative coordinates. It is 3D-specific; 2D can be embedded at z=0 with that limitation documented. Disable `sqrt-dist` when squared results suffice, and declare parallel build feature/thread count. Source `build.rs` unconditionally invokes cbindgen and writes `../examples/c/bosque.h` and `.hpp`; those parent directories/output permissions are a real packaging concern, not an algorithmic incompatibility. Arrange declared generated directories in a minimal build environment, or report a measured build failure. No such build was attempted here. Treat empty population and extreme-distance behavior explicitly.

**4. fnntw 0.4.1 — feasible all-N kNN adaptation for validated numerical domain, lifetime and extreme-distance caveats.** Primary: [pinned crate](https://crates.io/api/v1/crates/fnntw/0.4.1/download), [author feature definitions](https://github.com/cavemanloverboy/FNNTW/blob/main/Cargo.toml). `Tree<'t,f64,D>::new` borrows point storage; `query_nearest_k(q,N)` returns original input indices and distances (`src/query_k.rs`, `src/utils.rs`). Use owned immutable storage plus a safe owning/dependent wrapper, rebuilt after updates; do not use `Box::leak` each sample. Disable default features initially and enable only desired position/index/parallel behavior; the default `no-index` specifically affects axis-result types, while ordinary `QueryKResult` still has indices in this pin. All-N allocation/sort is unavoidable through this exposed path and must be charged. **Inspect before extreme inputs:** container starts with a max-finite dummy; `container.index` sets output length to requested k. If overflowing distances prevent filling k entries, uninitialized-length behavior is a source safety concern, not merely a wrong final filter. Guard the distance-safe domain before calling and use exact fallback outside it. Stable toolchain is declared; allocator features are optional. No build failure established.

**5. kdt 0.0.2 — feasible all-N kNN adaptation, genuine stable-toolchain blocker.** Primary: [pinned crate](https://crates.io/api/v1/crates/kdt/0.0.2/download), [author repository](https://github.com/TianyiShi2001/kdtree). `Point<f64,D>`, `KdTree::from_slice` and `k_nearest_neighbors` exist. Request all unique indexed positions, map each returned coordinate to its list of external IDs, expand and exact-filter; this handles `insert` rejecting equal points and avoids inventing a float ID dimension. Bulk builder can degenerate badly with coincident coordinates; bucket equal positions first and include that work. Empty input needs an adapter branch because `from_slice` indexes a midpoint unconditionally. Crate root has `#![feature(min_const_generics)]` and `#![feature(binary_heap_into_iter_sorted)]`, and calls `into_iter_sorted`: unchanged source cannot be compiled on stable. Use an explicitly pinned suitable nightly in a separate adapter build; do not label the algorithm incompatible or silently patch out the gates. Modern nightly compatibility remains untested.

**6. abd-clam 0.30.0 — real f64 range APIs, clustered exactness needs proof/validation.** Primary: [pinned crate](https://crates.io/api/v1/crates/abd-clam/0.30.0/download), [author repository](https://github.com/URI-ABD/clam). `VecDataset`, `Tree::new(...).partition(...)`, and `cakes::rnn::Algorithm::{Linear,Clustered}` expose range search returning `(index,distance)`. Dataset permutation requires `original_index` or metadata-to-ID mapping. Add separate linear and clustered entries. Linear can use a callback computing the registered squared metric and threshold r² in the normal domain, with the contract fallback for extremes. **Do not use squared Euclidean in clustered pruning:** cluster-radius/triangle-inequality bounds assume a metric; squared distance is not one. Clustered Euclidean broad-phase plus exact filtering requires conservative radius/bound rounding and must pass boundary/omission tests; final filtering cannot repair false negatives. Fixed-seed rebuilds are chargeable update work. automl/smartcore/rayon dependencies make it heavier, but no actual build blocker was established by this inspection.

## Different native coordinate models: candidate adaptations remain possible

**7. spatialtree 0.1.3 — adaptable cell/chunk index, not natively a point-radius API.** Primary: [pinned crate](https://crates.io/api/v1/crates/spatialtree/0.1.3/download), [official versioned documentation](https://docs.rs/spatialtree/0.1.3/spatialtree/). Store `Vec<(u64,[f64;D])>` in fixed-depth `CoordVec<D,u64>` chunks, using a declared world origin/cell mapping computed in f64/integer arithmetic; avoid `from_float_coords`, which takes f32. `iter_chunks_in_aabb` selects populated chunks through shared access, then exact-filter their points. Bound cell/depth domain, conservatively map query-box endpoints, and rebuild/rebase or fallback outside it. Preserve one cell's multiple entities rather than overwriting its chunk. Native coordinate depth is capped (`MAX_DEPTH=60`) and unsigned; directly casting arbitrary signed f64 is not a correct adapter. This is meaningful adapter work, not evidence the package is unrelated. GPL licensing is a separate metadata concern; keep benchmark dependency isolated from the public library.

**8. aabb-quadtree 0.2.0 — f32 XY broad phase possible, arbitrary f64 not native.** Primary: [pinned crate](https://crates.io/api/v1/crates/aabb-quadtree/0.2.0/download). Despite generic `S`, `Rect<S>` is `TypedRect<f32,S>`; `S` is the unit marker, not scalar type. Store IDs and full XYZ separately. Use f32 XY boxes enclosing point conversion error, expanded query boxes, and exact XYZ filtering. Set `allow_duplicates=true`: false removes objects sharing a bounding box, which violates distinct coincident IDs. Charge deduplication if broad-phase placement yields repeated candidates. Fixed root bounds, `my_intersects`, child pruning, and epsilon handling need boundary tests with outward padding; zero-area boxes are especially risky. For unrepresentable/unsafe f32 domains, use a declared exact fallback. This precision/proof gap is pending adapter validation, not an established build failure or blanket impossibility.

**9. quadtree 0.5.0 (Cargo) — f32 XY broad phase possible, distinct from the excluded npm package named quadtree.** Primary: [pinned crate](https://crates.io/api/v1/crates/quadtree/0.5.0/download), [author repository](https://github.com/benbaarber/quadtree). Point trait returns glam `Vec2` (f32); `Quadtree<T>` supports rectangle/shape queries, max_depth, and cloning items/references. Store original XYZ/u64 in T, build an enclosing XY projection, query an outward rectangle through `query_ref`/`query_filter`, then exact-filter. The built-in Circle computes f32 Euclidean membership and must not be used as the final contract predicate. Coalescing projected positions is optional if distinct IDs remain stored/expanded. Rebuild root when movement escapes; preserve failed-insert reporting. Precision loss alone does not establish incompatibility because a conservative broad-phase adapter can be tested. No hard build blocker found.

**10. spatial_hash 0.2.0 — implementable cube-cell enumerator, nightly plus f32-domain work.** Primary: [pinned crate](https://crates.io/api/v1/crates/spatial_hash/0.2.0/download), [author repository](https://github.com/JulianKnodt/regular_spatial_hash). Public active methods are `add`, cell `query` and `query_one_ring`; apparent `query_radius` is commented out. Cell coordinates are f32→i32. Use the cube mode, enumerate every intersecting cell of a conservative query box, call cell queries using validated interior representatives, and exact-filter original XYZ. Do not use one ring for arbitrary radii. Deduplicate cell visits if f32 rounding maps representatives to the same key. Need a declared coordinate/cell-ratio domain and exact fallback for large ratios/overflow. Rebuild coalesced updates because no per-ID removal API is evident. Crate enables `generic_const_exprs` and other feature attributes: stable cannot build unchanged source; pin compatible nightly and record the result. This is not native full-f64 support, but remains a real adapter candidate.

**11. unibn-octree, commit 8e3927d48d5ce61f94aab6090d77b4434f87dc89 — difficult conservative f32 candidate, not native f64.** Primary: [pinned header](https://github.com/jbehley/octree/blob/8e3927d48d5ce61f94aab6090d77b4434f87dc89/Octree.hpp). PointT does not imply double arithmetic: coordinate accessors, node centers/extents, radius, distance and pruning are float. Leaf acceptance and overlap use strict `<`, so a same-radius query omits exact boundary matches. Candidate adaptation needs an outward radius covering conversion **and distance arithmetic**, plus proof nodes conservatively enclose converted points over the chosen domain; a simple double PointT or one `nextafter` is insufficient without that analysis. A bounded exact binary lattice/minExtent setup may be provable and is worth implementing/testing, with final f64 filtering and timed rebuilds. Full arbitrary finite f64 needs explicit fallback outside the proof domain. Keep pending until a proof or concrete counterexample settles the adapter. Header-only source has no apparent dependency/build blocker; no compile test performed.

**12. quadtree-ts 0.0.1 — binary64 JS box query feasible, packaging and recursion defects need adapter handling.** Primary: [exact npm metadata](https://registry.npmjs.org/quadtree-ts/0.0.1), [exact source tarball](https://registry.npmjs.org/quadtree-ts/-/quadtree-ts-0.0.1.tgz). Published CommonJS `dist/main/QuadTree.js` uses JS Numbers and closed box tests in `utils.js`; XYZ radius can use XY broad phase plus exact final filtering. It is absent from the current npm package.json/lock, so installation/pinning is simply unfinished. Tree splits after four items with **no max-depth/min-width condition**; enough coincident XY points can recurse indefinitely. Bucket identical XY into one indexed representative retaining all original IDs; guard near-coincident coordinates whose subdivision cannot make progress, and retain an exact overflow bucket/fallback. Root must include all projected points. `query(shape)` contains unconditional `console.log` calls including per-item logging; suppress that logger explicitly in the benchmark adapter, disclose the harness override, and charge query/filter allocations. Do not remove algorithm code to improve timings. No TypeScript compilation is required because compiled JS is shipped. ## Recommended implementation order and coverage closure

1. Add collision's custom closed visitor and kdtree-plusplus box adapter first; they have clear native-f64 broad-phase designs and no established build blocker.
2. Add bosque/fnntw all-N entries with permutation/lifetime safeguards, then abd-clam linear/clustered entries separately. These are legitimate competitors even if all-N reporting proves slow.
3. Add the cell/chunk and f32 XY adapters with a registered conservative projection domain, explicit timed fallback, and full-membership tests. Build kdt/spatial_hash with a recorded nightly rather than rewriting upstream source unnoticed.
4. Resolve unibn's pruning precision and quadtree-ts's recursion/logging through concrete adapter proofs/tests; keep unresolved cases pending and the gate open.

For every adapter test exact-boundary/nextafter, radius zero, coincident distinct IDs, out-of-root motion, negative coordinates, arbitrary unindexed centers, unequal radii, extreme finite inputs, and empty collections. Record native-domain coverage and fallback counts/bytes. A successful build is not correctness evidence; a missing radius method is not incompatibility; adapter-implemented is not a passed performance gate.
