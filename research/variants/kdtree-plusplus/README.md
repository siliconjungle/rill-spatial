## Interface and lifecycle

`Native(input_points, cell_size)`, `update(vector<pair<uint32_t,Point>>)`, `prepare()`, and const `query(centre,radius,out)` match the native harness. The unused cell size does not tune this tree. IDs are the stable input row indices, represented as u64 in every output, exactly as required by this harness; constructor/update signatures do not accept application-selected external IDs. Duplicate coordinates retain separate original row IDs. Repeated updates to one ID keep the last position. Invalid updates and queries validate before mutation/output clearing.

All authoritative points live in one adapter vector. Update marks the prepared snapshot dirty; `prepare` coalesces all pending changes into one complete native `efficient_replace_and_optimise` build. Build and preparation allocations, sorting, original native optimisation, and old-tree retirement execute inside the parent's build/update timers. Queries before preparation remain current through a charged exact scan. A failed replacement leaves the old tree intact and the dirty flag set. This static adapter does not implement insertion/removal because the native comparison interface has fixed population.

## Duplicates and native layout

The source supports public custom accessor/comparator types. The adapter indexes a key `(binary64 axis coordinate, stable u64 ID)` on every axis, using ordinary double order followed by ID order. No coordinate is perturbed or narrowed. A record's unique ID makes per-axis keys distinct even when all XYZ coordinates coincide, so the source's median-optimised insertion does not collapse coincident records into one one-sided chain. This uses the original tree implementation, not an adapter-owned spatial traversal.

Box query keys are `(low_coordinate,0)` through `(high_coordinate,UINT64_MAX)`. Consequently, every ID at either spatial endpoint is included. The ID tie-break affects ordering/layout only. Native closed region overlap/enclosure chooses the candidate records; a copy-assignable `ReportVisitor` exact-filters and directly appends accepted u64 IDs, without an intermediate candidate-result vector or dedup pass. The upstream recursion assigns its visitor, so the adapter uses pointer members rather than a C++17 captured lambda. It adds no type-erasure allocation; all visitor/filter/output work remains inside query timing.

## Conservative candidate proof and fallback

Assume IEEE binary64 round-to-nearest, correctly rounded `sqrt`, and the host's ordered non-FMA squared predicate. Native lookup is used only for `1e-150 <= r <= 1e150`; its rounded `R=r*r` is positive, finite and normal.

For a matching point, every rounded nonnegative component square is <= the final ordered nonnegative sum, hence <=R. Therefore its exact pre-rounding square is below `nextUp(R)`. `nextUp(sqrt(nextUp(R)))` bounds the magnitude of its rounded subtraction result, allowing for sqrt rounding. One further `nextUp` bounds the exact coordinate difference before subtraction rounding. Set this as half-width h. Compute each box endpoint as `nextDown(c-h)` and `nextUp(c+h)`; outward endpoint rounding conservatively includes every point accepted by the host predicate. This avoids relying on an unproved fixed `1e-9` radius inflation. Extra candidates are removed by the unchanged final predicate.

Native source `_Region::encloses` and `_Region::intersects_with` reject only strictly outside keys. Its child bounds are copied/clipped with original split keys. Together with sentinel IDs and the native tree ordering invariant, they preserve candidate completeness for that conservative closed box. The parent validated full membership on the nine registered normal-domain fixtures; the broader floating-point argument and fallback contract still require explicit boundary/extreme validation and are not a passed full-contract gate.

Radius zero, smaller/larger radii, non-nearest current rounding mode, nonfinite expanded box endpoints, and dirty snapshots use a full authoritative-point scan. Radius zero tests coordinate equality (including signed-zero equality). Extreme radii use ordered `std::hypot` accumulation; normal radii use the host's `squared` helper. The fallback is inside query timing. Full cross-language parity of the platform's `std::hypot` with the Rust oracle still needs explicit extreme/boundary tests. The native harness's existing raw-square oracle cannot itself certify the Rust extreme-radius contract; use a matching general oracle when testing those values.

Output storage is the caller's one complete u64 vector; capacity and the potentially full-population result remain real costs. No observer×entity matrix, dependency copy, worker pool or global scratch buffer is added. Read-only queries have no adapter mutation and require distinct caller-owned outputs; mutation/preparation requires exclusive external ownership.
